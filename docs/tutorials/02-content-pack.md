# Tutorial 2: Building a content pack

A content pack is a folder of JSON files with an `index.json`. GloomFoundry's importer reads it
and fills **world compendiums** (one per pack you declare), sorted into folders. You can edit the
files, import again, and every compendium is rebuilt.

The finished result of this tutorial is [`docs/example-pack/`](../example-pack/): open it next to
this page.

## 1. The folder

```
my-pack/
├── index.json
├── classes/
│   ├── lantern-warden.json          the Class item
│   └── lantern-warden-powers.json   its Talents, Skills and Perks
├── equipment/items.json
├── backgrounds/backgrounds.json
├── bestiary/
│   ├── ash-wisp.json                an enemy (NPC actor)
│   └── lantern-spirit.json          a summon (NPC actor)
└── art/                             optional images
```

The layout is up to you: only `index.json` decides what is imported.

## 2. `index.json`

```json
{
  "name": "My homebrew",
  "packs": [
    {
      "name": "example-classes",
      "label": "Example: Classes",
      "type": "Item",
      "files": [
        { "path": "classes/lantern-warden.json", "folder": "Lantern Warden" },
        { "path": "classes/lantern-warden-powers.json", "folder": "Lantern Warden" }
      ]
    },
    {
      "name": "example-bestiary",
      "label": "Example: Bestiary",
      "type": "Actor",
      "files": [{ "path": "bestiary/ash-wisp.json", "folder": "Wisps" }]
    }
  ]
}
```

- `name` is the compendium's id (lowercase, digits, dashes); `label` is what you see.
- `type` is `Item`, `Actor` or `JournalEntry`.
- `folder` puts the file's documents in that compendium folder (use `/` for subfolders:
  `"Armor/Body"`). Skills are further sorted by level, Backgrounds by category.
- An optional `"iconPack": "icons/iconpack.json"` replaces the default icons (see the
  [icon pack reference](../reference/icon-pack.md)).

## 3. A document

Each file holds one document or an array of documents, in Foundry's usual format: `name`,
`type`, `img`, `system` (the GloomFoundry fields) and `flags`. A Skill:

```json
{
  "name": "Beacon",
  "type": "skill",
  "img": "icons/svg/book.svg",
  "system": {
    "source": "class",
    "level": 1,
    "initiative": 15,
    "primary": "<p>Attack 2, range 3, target 2. Infuse Light.</p>",
    "secondary": "<p>Heal 2, range 2.</p>",
    "lostOnUse": false,
    "actions": {
      "primary": [
        { "kind": "attack", "value": 2, "relative": false, "range": 3, "targets": 2, "pierce": 0, "area": null, "conditions": [] },
        { "kind": "infuse", "elements": ["light"], "either": false }
      ],
      "secondary": [
        { "kind": "heal", "value": 2, "self": false, "range": 2, "conditions": [] }
      ]
    }
  },
  "flags": { "gloomfoundry": { "class": "Lantern Warden", "source": "My homebrew" } }
}
```

- Text fields are HTML (`<p>...</p>`).
- `actions` is optional: without it, buttons are read from the text (see
  [Tutorial 1](01-by-hand.md#how-the-buttons-are-made)). With it, you decide exactly which buttons
  appear and the text is kept as a tooltip. [Tutorial 3](03-actions.md) explains how to write them.
- `flags.gloomfoundry.class` ties the Skill to its class for the Level up dialog.
- `flags.gloomfoundry.source` is free text (where it comes from).

Every field is listed in the [item types reference](../reference/item-types.md). Fields you leave
out take their default value.

## 4. The class and its grants

The Class item lists, in `system.grants`, **full copies** of the items a new character gets
(Level 1 Talents, starting Skills, Perks), and in `system.startingItems` the starting equipment.
Writing them twice by hand is error-prone; the example pack is generated by a small script that
copies the powers into the class. Any tool works; just keep the class's grants in sync with the
powers file.

## 5. Images

Image paths are either Foundry paths (`icons/svg/fire.svg`, core icons that always exist) or
paths **relative to `index.json`** starting with `./`:

```json
"img": "./art/ash-wisp.webp",
"prototypeToken": { "texture": { "src": "./art/ash-wisp.webp" } }
```

The importer turns `./` paths into full paths, so the folder can be uploaded anywhere.

## 6. Check it

```sh
node tools/validate-pack.mjs my-pack/index.json
```

Fix the errors. Warnings are worth reading: for example a Skill without
`flags.gloomfoundry.class` is never offered by the Level up dialog.

## 7. Upload it

**Self-hosted Foundry**: copy the folder into your user data, for example
`Data/gloomfoundry-content/`.

**The Forge**: open the **Assets Library**, create a folder (e.g. `gloomfoundry-content`) and
upload the whole pack into it, keeping the subfolders.

## 8. Import it

As the GM: **Game Settings → Configure Settings → GloomFoundry → Import content into
compendiums**, then **Choose index.json** and pick your `index.json`.

The compendiums appear in the Compendium sidebar. **Import again** (same menu) rebuilds them after
you change the files: it empties the packs it imports into, so don't edit those compendiums by
hand (copy items to the world first).

Characters that already have items from an earlier import can pick up the changes with the
**Refresh items** button on their Progression tab: it updates each item from the compendium and
keeps its state (expended, prepared, equipped, quantities...).

## Sharing

A pack of your own homebrew is yours to share. A pack made from the rulebook is for your own
table: keep it private (a private Forge assets folder, a private repository).
